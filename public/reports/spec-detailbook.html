DetailBook은 범용 예약 도구(Calendly, Square)가 다루지 못하는 차량 정보 기반 예약과 세라믹코팅 보증 추적이라는 디테일링 업종 고유의 니즈를 해결한다. 차량 CRM과 예약 시스템의 결합이 핵심 가치이자 방어벽이다.

02 — 핵심 문제 정의

현재 소규모 오토디테일링 사업자들이 겪는 운영 문제는 다음과 같다.

문제 현재 대안 결과
전화/문자 기반 예약 수동 관리 노쇼율 15~25%, 매출 손실
고객/차량 정보 관리 Instagram DM, 스프레드시트 정보 분산, 검색 불가, 유실 위험
차량별 서비스 이력 추적 수기 노트 또는 기억에 의존 코팅 보증 관리 불가, 재방문 유도 실패
차량 크기별 가격 차등 Calendly, Square 등 범용 도구 차량 정보를 다루지 못해 수동 견적 필요
고객 재방문 유도 없음 반복 매출 기회 상실

핵심 인사이트: 디테일링 사업의 단위는 "고객"이 아니라 "차량"이다. 한 고객이 여러 차량을 보유하며, 서비스 이력과 보증은 차량 단위로 관리되어야 한다. 기존 도구 중 이 구조를 지원하는 제품이 없다.

03 — 기능 명세 (MVP)

아래 5개 모듈을 MVP 범위로 정의한다. 5~7주 내 구현 가능한 수준으로 스코프를 제한하되, 핵심 가치를 완전히 전달하는 것을 우선한다.

3.1 온라인 예약 위젯 (Online Booking Widget)

기능 요건

  • 서비스 종류 선택 — 외부세차, 내부클리닝, 풀디테일, 세라믹코팅, PPF 등 사업자가 설정한 서비스 메뉴에서 선택
  • 차량 정보 입력 — 연식, 제조사, 모델, 차량 크기(세단/SUV/트럭 등) 선택 시 자동 가격 조정
  • 날짜/시간 선택 — 디테일러의 가용 시간 기반 캘린더 표시. 이미 예약된 슬롯은 비활성화
  • 사진 업로드 — 차량 현재 상태 사진 1~5장 첨부 (선택 사항)
  • 보증금 결제 — Stripe 결제 연동. 서비스 가격의 N% (사업자 설정)를 보증금으로 수령하여 노쇼 방지
  • 임베드 지원 — Web Component (Shadow DOM)로 구현하여 고객의 기존 웹사이트에 <script> 한 줄로 삽입 가능

예약 플로우

  1. 서비스 선택 — 카드형 UI로 서비스 목록 표시. 각 카드에 서비스명, 설명, 기본 가격, 소요시간 표기
  2. 차량 정보 — 연식(드롭다운), 제조사(검색 가능 드롭다운), 모델(제조사 연동), 크기 카테고리(자동 매핑 + 수동 변경 가능). 기존 고객이면 등록된 차량에서 선택
  3. 날짜/시간 — 월간 캘린더에서 날짜 선택 후 해당 일의 가용 시간 슬롯 표시. 서비스 소요시간을 반영한 연속 슬롯만 활성화
  4. 사진 업로드 — 드래그앤드롭 또는 파일 선택. 최대 5장, 각 10MB 이하. 업로드 프리뷰 제공
  5. 보증금 결제 — 최종 가격(기본가 x 크기 배수) 표시 + 보증금 금액 표시. Stripe Elements로 카드 결제
  6. 확인 — 예약 번호, 날짜/시간, 서비스, 차량 정보, 결제 금액 요약. SMS/이메일 확인 전송
가격 계산 로직: 최종 가격 = 서비스 기본가 x 차량 크기 배수. 예: 풀디테일($200) x SUV(1.3x) = $260. 보증금 = $260 x 30% = $78.

3.2 차량 CRM (Vehicle CRM)

고객 프로필

  • 기본 정보: 이름, 이메일, 전화번호
  • 보유 차량 목록 (1:N 관계)
  • 태그/세그먼트: VIP, 정기고객, 잠재고객, 신규 등 사용자 정의 태그
  • 자유 메모 필드
  • 생성일, 마지막 방문일 자동 기록

차량 카드

  • 차량 기본 정보: 연식, 제조사, 모델, 색상, 크기 카테고리
  • VIN 번호 (선택 입력)
  • 차량 사진 (복수)
  • 서비스 이력 타임라인 — 날짜, 서비스 종류, 가격, 비포/애프터 사진을 시간순으로 표시
  • 세라믹코팅 보증 추적 — 설치일, 보증 기간, 다음 유지보수 날짜, 보증 상태(활성/만료)
  • 특이사항 메모 — 예: "좌측 뒷범퍼 스크래치 주의", "실내 가죽 시트 특수 관리 필요"

검색 및 필터

  • 고객명, 전화번호, 차량 정보로 통합 검색
  • 태그별 필터링
  • 마지막 방문일 기준 필터 (30일/60일/90일 이상 미방문)
  • 코팅 보증 상태별 필터 (활성/만료 예정/만료)

3.3 자동 커뮤니케이션 (Automated Communications)

Twilio를 통한 SMS 및 이메일 자동 발송. 모든 메시지는 사업자 브랜드명으로 발송되며, 발송 로그를 기록한다.

트리거 채널 타이밍 내용
예약 확인 SMS + 이메일 예약 완료 즉시 예약 일시, 서비스명, 차량 정보, 보증금 수령 확인
예약 리마인더 SMS 예약 24시간 전 예약 일시 재확인, 취소/변경 링크 포함
서비스 완료 SMS + 이메일 상태 완료 변경 시 감사 메시지, Google Review 링크, 애프터 사진 갤러리 링크
코팅 유지보수 SMS 다음 유지보수일 2주 전 유지보수 시기 안내, 예약 링크 포함
재방문 유도 SMS 마지막 방문 후 N개월 재방문 권유, 예약 링크 포함. N값은 사업자 설정
비용 주의: Twilio SMS 비용은 건당 약 $0.0079 (미국 국내). 고객 1인당 월 평균 3~5건 발송 시 고객당 월 $0.02~0.04 수준이나, 고객 수 증가 시 누적 비용 관리 필요. 이메일 우선 발송 옵션으로 SMS 비용 절감 가능.

3.4 대시보드 (Dashboard)

주요 지표

  • 오늘/이번주 예약 캘린더 — 일간/주간 토글. 각 예약 블록에 고객명, 차량, 서비스, 상태 표시
  • 월 매출 요약 — 완료된 서비스 기준 총 매출, 건수, 평균 단가
  • 노쇼율 — 월간 기준 노쇼 건수 / 총 예약 건수. 보증금 도입 전후 비교 가능
  • 고객 재방문율 — 2회 이상 방문 고객 비율
  • 코팅 보증 만료 예정 — 30일 내 보증 만료 예정인 차량 목록. 유지보수 리마인더 발송 상태 포함

알림 패널

  • 내일 예약 건수 요약
  • 미수금 내역 (보증금만 결제, 잔액 미결제)
  • 보증 만료 임박 차량
  • N개월 미방문 고객 (재방문 유도 대상)

3.5 설정 (Settings)

서비스 메뉴 관리

  • 서비스 추가/편집/삭제: 서비스명, 설명, 기본 가격, 소요시간 (분)
  • 서비스 활성/비활성 토글
  • 드래그앤드롭 정렬 순서 변경

가격 설정

  • 차량 크기별 가격 배수 설정 — 기본값: 세단 1.0x, SUV 1.3x, 트럭 1.5x
  • 보증금 비율 설정 — 서비스 가격의 N% (기본값 30%)

영업 설정

  • 요일별 영업 시간 설정 (시작/종료)
  • 특정 날짜 휴무 설정
  • 예약 간 버퍼 시간 설정 (이동 시간 등)

연동

  • Stripe — Stripe Connect를 통한 보증금 수령. OAuth 연동 플로우
  • Google Calendar — 예약을 Google Calendar에 자동 동기화. 양방향 동기화는 MVP 이후
  • Twilio — SMS 발송용 계정 연동. 사업자의 Twilio 계정 또는 DetailBook 공유 계정 선택

04 — 기술 스택

영역 기술 선정 근거
프론트엔드 Next.js 14 (App Router) + Tailwind CSS RSC로 서버 렌더링 최적화. Tailwind로 빠른 UI 개발. Vercel 배포 최적화
백엔드/DB Supabase (PostgreSQL + Auth + Storage + Realtime) 인증/스토리지/실시간 기능 통합 제공. Row Level Security로 멀티테넌트 보안. 1인 개발에 적합한 생산성
결제 Stripe (Stripe Connect) 보증금 수령 및 사업자 정산. Connect로 각 사업자 계정에 직접 입금
SMS/이메일 Twilio SMS + 이메일 통합 발송. 미국 번호 지원. 프로그래매틱 API
배포 Vercel Next.js 네이티브 호스팅. 프리뷰 배포, Edge Functions, 자동 스케일링
예약 위젯 Web Component (Shadow DOM) 고객 웹사이트의 기존 스타일과 충돌 없이 임베드 가능. 프레임워크 무관
Web Component 배포 방식: 예약 위젯은 별도 번들로 빌드하여 CDN에 호스팅한다. 고객은 <script src="https://widget.detailbook.app/v1.js"></script>와 <detail-book id="사업자ID"></detail-book> 두 줄만 추가하면 된다.

5.8 ER 관계 요약

  • users 1:N services — 사업자가 서비스 메뉴를 관리
  • users 1:N customers — 사업자별 고객 목록
  • customers 1:N vehicles — 고객이 여러 차량 보유 가능
  • users 1:N bookings — 사업자의 예약 목록
  • bookings N:1 customers, vehicles, services
  • vehicles 1:N coatings — 차량별 코팅 이력
  • coatings N:1 bookings — 코팅은 특정 예약에서 시공
  • communications_log N:1 bookings, customers

5.9 인덱스 전략

  • bookings(user_id, scheduled_at) — 캘린더 조회 성능
  • bookings(user_id, status) — 상태별 필터링
  • customers(user_id, phone) — 전화번호 검색
  • vehicles(customer_id) — 고객별 차량 조회
  • coatings(vehicle_id, next_maintenance_at) — 유지보수 알림 스케줄링
  • communications_log(customer_id, sent_at) — 발송 이력 조회

06 — 화면 설계

각 화면의 구조와 핵심 요소를 정의한다. 상세 와이어프레임은 별도 Figma 문서에서 관리한다.

6.1 대시보드 (메인 화면)

목적: 오늘의 업무 파악과 핵심 지표 모니터링

  • 상단 바 — 오늘 날짜, 예약 건수 배지, 예상 매출 금액
  • 캘린더 영역 (좌측 70%) — 일간/주간 토글. 시간축 세로 배치. 각 예약 블록에 고객명, 차량(연식+모델), 서비스명, 상태 색상 표시. 클릭 시 우측 상세 패널 활성화
  • 상세 패널 (우측 30%) — 선택된 예약의 전체 정보. 상태 변경 버튼 (확인/완료/노쇼/취소). 비포/애프터 사진 업로드. 고객 프로필 링크
  • 하단 알림 영역 — 보증 만료 예정 차량, 미수금 내역, 미방문 고객 알림. 각 항목 클릭 시 상세 페이지 이동

6.2 예약 페이지 (고객용)

목적: 고객이 직접 예약하고 보증금을 결제하는 공개 페이지

  1. 서비스 선택 — 카드형 그리드. 서비스명, 간단 설명, "가격 $X부터", 소요시간 표시. 단일 선택
  2. 차량 정보 — 전화번호 입력으로 기존 고객 확인. 기존 고객이면 등록된 차량 목록에서 선택 또는 신규 추가. 신규이면 연식/제조사/모델 입력 (크기 카테고리 자동 매핑). 최종 가격 실시간 계산 표시
  3. 날짜/시간 — 월간 캘린더. 가용일만 선택 가능. 선택 후 해당 일의 시간 슬롯 표시. 서비스 소요시간 + 버퍼를 반영한 연속 가용 슬롯만 표시
  4. 사진 업로드 (선택) — 차량 현재 상태 사진. 드래그앤드롭. 최대 5장. 스킵 가능
  5. 보증금 결제 — 주문 요약 (서비스, 차량, 일시, 총액, 보증금). Stripe Elements 카드 입력. 결제 버튼
  6. 확인 화면 — 예약 번호, 전체 요약, "SMS/이메일로 확인이 발송됩니다" 안내

6.3 고객 상세 (Customer Detail)

목적: 고객과 보유 차량의 전체 이력을 한 화면에서 파악

  • 고객 정보 헤더 — 이름, 연락처, 태그, 총 이용 횟수, 총 지출 금액, 최초/최근 방문일
  • 차량 목록 — 탭 또는 카드형. 각 차량에 연식/제조사/모델/색상, 코팅 보증 배지(활성 초록/만료 빨강/없음 회색)
  • 서비스 이력 타임라인 — 선택된 차량의 시술 이력. 날짜, 서비스명, 금액, 비포/애프터 사진 썸네일. 시간순 정렬
  • 코팅 보증 상세 — 코팅 종류, 시공일, 보증 만료일, 다음 유지보수일, 잔여 보증 기간 프로그레스 바
  • 커뮤니케이션 로그 — 해당 고객에게 발송된 모든 SMS/이메일 내역. 발송일, 종류, 상태
  • 메모 영역 — 고객/차량 특이사항. 자유 텍스트. 저장 시 타임스탬프 기록

6.4 설정 (Settings)

목적: 사업 정보와 서비스 구성을 관리

  • 서비스 메뉴 탭 — 서비스 목록 편집. 드래그 정렬. 인라인 편집 또는 모달
  • 가격 설정 탭 — 차량 크기 카테고리 목록과 각 배수 입력. 보증금 비율 슬라이더
  • 영업 시간 탭 — 요일별 시작/종료 시간. 특정 날짜 휴무 캘린더
  • 연동 탭 — Stripe 연결 상태 + 연결/해제 버튼. Google Calendar 동기화 토글. Twilio 설정

경쟁 방어벽

  • 차량 CRM — 범용 예약 도구는 "누가 예약했는가"만 추적하지만, DetailBook은 "어떤 차량에 어떤 서비스를 했는가"를 추적한다. 이 데이터 구조의 차이가 전환 비용을 만든다.
  • 코팅 보증 추적 — 세라믹코팅은 고가 서비스($500~2,000+)이며 보증 관리가 필수적이다. 이 기능을 제공하는 경쟁자가 없다.
  • 축적 효과 — 고객이 차량 이력과 사진을 쌓을수록 전환 비용이 증가한다.

10 — MVP 타임라인

총 7주 일정. 1인 풀타임 개발 기준. 주차별 핵심 산출물을 정의한다.

  • Week 1 — 기반 구축
    Supabase 프로젝트 생성 및 DB 스키마 마이그레이션. Supabase Auth 설정 (이메일/비밀번호). Next.js 14 프로젝트 초기화 + Tailwind 설정. 기본 CRUD API (서비스, 고객, 차량). RLS 정책 적용. 레이아웃 및 네비게이션 구조 구현.
  • Week 2 — 예약 위젯
    예약 플로우 UI 구현 (5단계 스텝 폼). 서비스 선택 + 차량 정보 입력 + 날짜/시간 선택 화면. 가용 시간 슬롯 계산 로직. 사진 업로드 (Supabase Storage). Web Component 빌드 파이프라인 설정.
  • Week 3 — Stripe 결제 연동
    Stripe Connect OAuth 플로우 (사업자 온보딩). PaymentIntent 생성 + 보증금 결제 처리. 결제 성공/실패 핸들링. Webhook 수신 및 예약 상태 업데이트. 가격 계산 로직 (기본가 x 크기 배수 x 보증금 비율).
  • Week 4 — 차량 CRM
    고객 목록/상세 화면. 차량 카드 UI + CRUD. 서비스 이력 타임라인 컴포넌트. 비포/애프터 사진 갤러리. 코팅 보증 정보 입력/표시. 검색 + 태그 필터. 고객/차량 메모 기능.
  • Week 5 — 자동 알림 + 코팅 보증
    Twilio 연동 (SMS 발송 API). 예약 확인/리마인더 자동 발송 (cron job 또는 Supabase Edge Function). 서비스 완료 후 리뷰 요청. 코팅 유지보수 리마인더 스케줄러. 재방문 유도 메시지. communications_log 기록.
  • Week 6 — 대시보드 + 설정
    대시보드 메인 화면 (캘린더 뷰 + 지표 카드). 예약 상세 패널. 월 매출/노쇼율/재방문율 집계. 설정 화면 (서비스 메뉴, 가격, 영업 시간, 연동 상태). Google Calendar 동기화 (단방향: DetailBook → GCal).
  • Week 7 — 마무리
    통합 테스트 + 버그 수정. 예약 플로우 전체 E2E 테스트. 결제 플로우 테스트 (Stripe 테스트 모드). 랜딩 페이지 제작. Vercel 프로덕션 배포. 위젯 CDN 배포. 온보딩 가이드 작성.
스코프 경고: 7주 내 완료를 위해 다음은 MVP에서 제외한다 — (1) Google Calendar 양방향 동기화, (2) 다중 직원 계정, (3) 인보이스/견적서 생성, (4) 모바일 네이티브 앱, (5) 고급 보고서 (매출 분석, 서비스별 수익성 등). 이들은 출시 후 고객 피드백에 따라 우선순위를 결정한다.
