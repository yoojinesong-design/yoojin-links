# 안전장치 자세한 동작

README 7장의 요약 뒤에 있는 실제 동작이야. 봇을 실거래에 쓰기 전에 한 번은 읽어봐.

## 비상 명령

kill switch가 켜져 있는 동안 봇은 **아무 주문도 안 내.** 신규 매수만이 아니라 손절·익절 매도도 안 나가니까, 휴가처럼 오래 비울 때는 포지션을 먼저 정리하거나 kill switch 없이 손절에 맡겨. `flatten --yes`는 내가 직접 산 주식·코인까지 팔아 (아래 참고). 내 것도 들고 있으면 봇이 산 수량만 앱에서 직접 팔아. config를 고치다가 틀려도 (YAML 들여쓰기 실수 포함) `kill`/`resume`은 동작해 (config의 `state_dir`만 읽어). `status`와 `flatten`은 config 에러를 낼 때 실행 중인 봇을 멈추는 KILL 파일 경로를 같이 알려줘. Docker로 돌리면 이 명령들은 컨테이너 안에서 실행해 (README 4장 Docker 참고).

> **GitHub Actions로 돌리는 봇은 `kill`로 안 멈춰.** KILL 파일은 명령을 실행한 컴퓨터의 `state` 폴더에 생기는데, Actions는 매번 Actions cache에서 상태를 가져와서 그 파일을 못 봐. Actions 봇을 멈추려면 repo **Variables**의 `TRADING_BOT_ENABLED`를 `false`로 바꾸거나 `trading-bot` workflow를 disable해. 7일 넘게 멈추면 봇 상태가 지워지니까 README 4장의 주의사항을 꼭 봐.

## 매매·주문 규칙

- **Paper가 기본이야.** live는 config `mode: live`와 env `LIVE_TRADING_CONFIRM`이 둘 다 있어야 켜져.
- **Margin을 안 써.** Alpaca에서는 `non_marginable_buying_power`(실제 현금)만 써.
- **Short를 안 해.** 매도 수량은 보유 수량을 넘지 않아. 수량은 항상 내림(round down)해. margin 계좌에 내가 직접 연 short 포지션이 있으면 그 종목은 사지 않아 (사면 내 short를 덮어버리니까). 처음 발견하면 알림을 한 번 보내.
- **완성된 봉으로만 판단해.** 형성 중인 봉은 버려. 같은 봉에서는 한 번만 판단하고, 봇이 낸 주문이 아직 미체결이면 그 종목은 건너뛰어.
- **손절·익절은 (kill switch가 꺼져 있을 때) 항상 먼저 체크해.** 같은 종목에 내가 직접 넣은 주문(앱에서 건 지정가 등)이 있어도, 캔들 데이터를 못 받아도 손절은 돌아. 최신 시세 조회가 실패하면 브로커가 알려준 포지션 가격으로 손절을 체크해. 수동 주문이 있는 종목은 신규 매수만 멈춰. 수동 주문이 수량을 잡고 있어서 손절 매도가 거부되면 에러 알림을 보내.
- **체결 전 주문도 한도에 넣어.** 주문이 접수됐는데 아직 체결이 안 됐어도 (다음 tick까지 안 된 것도) 다른 종목을 계산할 때 포지션 수·투자 비중·현금 한도에 포함해.
- **봇은 자기가 산 것만 관리하고 팔아.** 봇이 직접 낸 주문으로 산 수량을 상태 파일에 기록해 두고, 손절·익절·전략 매도·`flatten_on_daily_loss`는 그 수량에만 적용해. 봇을 켜기 전부터 계좌에 있던 주식·코인은 `symbols`에 있는 종목이라도 봇이 **알아서 파는 일은 절대 없고**, 그 종목은 새로 사지도 않아 (내가 직접 `flatten --yes`를 치는 건 예외, 아래 참고). 처음 발견하면 알림을 한 번 보내고 `status`에도 표시해. 상태 파일이 없을 때(첫 실행, 또는 상태를 잃어버렸을 때)는 봇이 산 건지 알 수 없으니까 "봇이 산 기록이 없다"고 알려줘. 기존 보유분까지 봇이 관리하게(=팔 수도 있게) 하려면 config에 `adopt_existing_positions: true`를 넣어. (로컬 paper 계좌는 봇만 거래하니까 전부 봇 것으로 봐.) 코인 평균 매수가 파일도 계좌별(`ccxt_entries.<거래소>[.sandbox].json`)이라 testnet 기록이 live에 섞이지 않아.
- **paper↔live를 바꿔도 봇이 산 기록은 계좌별로 남아.** 같은 config에서 `mode`(paper↔live)나 `use_sandbox`만 바꿔도, 이전 계좌의 기록은 따로 보관했다가 다시 그 계좌로 돌아오면 이어서 손절·매도를 관리해. 다른 계좌를 도는 동안에는 그 계좌 포지션의 손절이 안 돌아. 계좌가 바뀌면 알림을 보내. 같은 브로커·같은 모드의 다른 계좌로 API 키만 바꾸는 건 구별 못 해 (README 11장 참고).
- **주문 결과가 불확실해도 봇 것으로 기록해.** 주문을 보내기 전에 상태 파일에 먼저 기록하고 저장해. 그래서 응답이 끊기거나(timeout) 주문 도중 프로세스가 죽어도, 실제로 체결된 매수는 봇이 산 것으로 남아서 손절이 계속 돌아. 매도는 체결된 만큼만 봇의 수량에서 빼. 주문이 끝나면 브로커에 그 주문의 실제 체결 수량을 조회해서 기록을 맞춰 (Alpaca는 봇이 붙인 주문 ID로 조회해서 응답이 끊긴 주문도 찾아내). Alpaca 조회가 잠깐 실패하면 다음 tick에 다시 조회하고, 그동안 그 종목은 팔지 않아 (그 사이 내가 직접 사고판 게 봇의 체결로 잘못 잡히지 않게). 조회를 지원하지 않는 거래소는 보유 수량 변화로 맞춰. 거래 정지 등으로 매도 주문이 체결 안 되고 만료·취소되면, 남은 수량은 여전히 봇 것이라서 다음 tick에 손절 매도를 다시 보내. 봇의 매수 주문이 아직 체결 중인 동안에는 그 종목을 팔지 않아 (그 사이 내가 산 주식과 구별이 안 되니까).
- **주식 분할(split)·병합도 따라가.** 브로커가 보유 수량과 평단가를 바꾸면(예: 2:1 분할 → 수량 2배, 평단 1/2) 봇이 산 수량과 평단가도 같이 맞추고 알림을 보내. 병합 때 1주 미만 끝수를 현금으로 받아서(cash in lieu) 수량이 딱 안 떨어져도 알아봐. 그래서 분할 때문에 가짜 손절이 나가거나, 병합 뒤에 손절이 꺼지거나, 내 몫까지 봇 것으로 잡히지 않아.
- **`flatten --yes`는 봇이 안 산 것까지 정리해.** Alpaca에서는 **계좌의 모든 포지션**(봇이 안 산 종목까지, 내가 margin 계좌에서 직접 연 short는 되사서)을 시장가로 정리하고, **계좌의 모든 미체결 주문**(포지션이 없는 종목에 건 것까지)을 취소해. 코인 거래소에서는 `symbols`에 있는 코인의 **잔고 전체**(내가 원래 들고 있던 코인까지)를 시장가로 팔고, 그 코인들의 미체결 주문을 내가 건 것까지 전부 취소해. 봇이 산 것만 정리하고 싶으면 `flatten` 대신 앱에서 그 수량만 팔아. 반면 `flatten_on_daily_loss`는 봇이 산 포지션만 팔고, **봇이 낸 매수 주문만** 취소해. 내가 직접 건 주문(내 주식에 건 손절 주문 등)은 그대로 둬.
- **`symbols`에서 뺀 종목은 관리 안 해.** 아직 들고 있으면 손절도 매도도 안 해. 봇이 한 번 알림을 보내고 `status`에도 표시해 (Alpaca와 로컬 paper만. 코인 거래소는 README 11장 참고).
- **일일 손실 한도는 매매 손익만 봐.** 장중에 입금·출금하거나, 봇이 평가하지 않는 자산(코인 계좌에서 `symbols`에 없는 코인)을 직접 사고팔아서 현금이 움직이면, 그만큼 그날의 기준 자산을 조정해. 수량이 바뀐 보유 종목은 이번 tick의 가격으로 계산해서, 급락 중에 내가 직접 판 손실이 출금으로 둔갑해 가려지지 않아. 그 가격을 못 읽으면 (조회 실패, Alpaca 계좌의 코인·옵션처럼 봇이 시세를 못 읽는 자산) 옛 가격으로 계산하지 않고 그 tick은 입출금을 건너뛰어 (그 사이에 들어오거나 나간 돈은 손익으로 계산돼). 봇의 주문이 체결되는 중에는 (주문 직후 1–2 tick, 거부된 주문은 빼고) 계좌 조회와 포지션 조회 사이에 체결이 끼어 봇 자신의 매매가 입출금처럼 보일 수 있어서, 그동안은 입출금 추적을 쉬어. Alpaca는 기준값이 뉴욕 전일 종가라서, config의 `timezone`과 상관없이 하루를 뉴욕 날짜로 세 (Alpaca config의 백테스트도 똑같이). 장 마감 후 입출금처럼 못 잡는 경우는 README 11장 참고.
- **같은 state 폴더로는 봇이 하나만 돌아.** instance lock이 있어서, 이 컴퓨터에서 같은 `state_dir`를 쓰는 봇은 동시에 두 개가 못 돌아 (Windows 포함). 하지만 `state_dir`이 다른 config 두 개, 다른 컴퓨터, GitHub Actions + 내 컴퓨터/Docker처럼 **같은 계좌를 따로 돌리는 건 못 막아.** 한 계좌에는 봇 하나만 돌려 (같이 사면 비중 한도가 두 배가 되고, 서로의 포지션은 "안 산 것"으로 봐서 손절도 안 해).
- **에러가 나도 안 죽어.** 에러는 기록하고 재시도해. 계좌 조회 실패처럼 tick 전체가 실패하면 backoff하고, 종목 하나의 에러나 상태 파일 에러는 손절 체크를 늦추지 않아. 연속으로 에러가 나면 마지막 에러 내용과 함께 알림을 보내.
- **상태 파일이 계좌보다 오래됐으면 아무 주문도 안 내.** 봇은 주문을 낼 때마다 그 주문 ID를 상태 파일에 먼저 기록해. Alpaca에서는 봇이 시작할 때(`once`는 매번) 주문 내역을 보고, 상태 파일이 모르는 봇 주문이 있으면 (저장이 안 된 실행이 있었거나, 다른 봇이 같은 계좌를 쓰는 경우) 봇이 산 기록이 틀렸을 수 있으니까 **손절까지 포함해 아무 주문도 안 내고** 에러를 알려. 앱에서 포지션을 확인해서 봇이 산 건 직접 정리하고, 봇을 멈춘 뒤 상태 파일을 지우고 다시 시작해 (Actions는 `fresh_state`로 실행).
- **상태 파일을 못 저장하거나 못 읽으면 신규 매수를 멈춰.** 주문을 내기 전에 먼저 저장해 보고, 실패하면 (디스크가 꽉 찼을 때 등) 오늘 거래 수·일일 손실 정지는 메모리에서 계속 세면서 저장이 다시 될 때까지 매도·손절만 해. `once`(cron)로 돌릴 때도 마찬가지야. 파일을 못 읽으면(권한 문제, 손으로 고치다 깨진 내용 등) 덮어쓰지도 옮기지도 않고, 돌고 있던 봇은 기억하는 포지션의 손절·매도만 계속해. 그동안 봇이 주문을 냈으면 저장이 다시 될 때 기억하는 쪽으로 덮어써 (예전 파일로 돌아가면 이미 판 수량을 다시 팔 수 있으니까). 새로 시작한 봇(`once`, 재시작)은 기억이 없어서 봇이 산 걸 구별 못 하니까, 파일을 고치거나 지울 때까지 에러를 알려. 지우면 봇이 산 기록도 사라져서 그 포지션은 손절이 안 돌아. 돌고 있는 봇의 상태 파일이 없어지면 기억하는 걸로 다시 써 (정말 처음부터 하려면 봇을 먼저 멈추고 지워). 상태 파일은 일반 권한(0644)으로 저장돼서 `sudo`로 한 번 돌려도 서비스 사용자가 계속 읽을 수 있어.
- **기록이 남아.** 모든 주문(수동 `flatten` 포함)은 `logs/<이름>/trades.csv`, 전체 로그는 `logs/<이름>/bot.log`에 남아.

## GitHub Actions로 돌릴 때

> ⚠️ **Actions로 실거래하기 전에 꼭 알아둬.**
> - **public repo면 로그가 전부 공개돼.** 누구나 매 실행의 로그와 logs artifact(자산, 보유 종목, 모든 주문)를 볼 수 있어. `mode: live`는 **private repo**에서만 돌려.
> - **public repo는 60일 동안 커밋이 없으면 GitHub이 schedule을 자동으로 꺼.** 그러면 손절 체크도 멈추는데, 봇은 안 돌고 있으니까 알림도 못 보내. private repo를 쓰거나, 60일 안에 한 번은 커밋하거나, VPS/Docker로 돌려. 가끔 Actions 탭에서 workflow가 꺼지지 않았는지 확인해.
> - **봇의 기억(봇이 산 수량)은 Actions cache에만 있고, GitHub은 7일 동안 안 쓴 cache를 지워.** `TRADING_BOT_ENABLED`를 끄거나 workflow를 disable해서 7일 넘게 멈추면 상태가 사라져. 그러면 다음 실행은 매매하지 않고 `Restore bot state` 단계에서 실패해서 알려줘 (빈 상태로 돌면 봇이 산 종목을 잊어서 그 손절이 영영 꺼지니까). 그땐 봇이 산 종목을 앱에서 직접 정리하고 `fresh_state`로 다시 시작하거나, `adopt_existing_positions: true`를 넣고 `fresh_state`로 실행해 (그러면 `symbols`에 있는 내 보유분까지 봇이 관리하고 팔 수 있어). 오래 비울 거면 멈추기 전에 포지션부터 정리해.
> - **상태 저장이 실패하면 그 실행이 실패로 떠.** cache 서비스 장애 등으로 저장이 안 되면 `Check the bot state was saved` 단계에서 실패해 (GitHub이 실패 메일을 보내줘). 그러면 다음 실행은 그 전의 오래된 상태를 가져오는데, 봇이 Alpaca 주문 내역에서 상태 파일이 모르는 봇 주문을 찾으면 **손절까지 포함해 아무 주문도 안 내고** 매 실행마다 에러를 알려 (오래된 기록으로 매매하면 내 주식을 팔 수 있으니까). 그땐 앱에서 포지션을 확인해서 봇이 산 건 직접 정리하고 `fresh_state`로 다시 시작해.
