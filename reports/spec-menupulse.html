1. 제품 개요

MenuPulse는 독립 레스토랑 오너와 셰프를 위한 B2B 마켓 인텔리전스 도구이다. 소셜 미디어와 검색 트렌드에서 지금 뜨는 메뉴 아이디어를 발굴하고, 식자재 원가 변동을 자동으로 추적하며, 경쟁 식당의 메뉴와 가격을 모니터링하여 데이터 기반의 메뉴 의사결정을 가능하게 한다.

2. 핵심 문제 정의

독립 레스토랑 오너는 다음과 같은 문제를 직면하고 있으며, 현재 시장에는 이를 적정 가격에 해결하는 도구가 없다.

문제 현재 상태 영향
트렌드 파악 부재 "지금 뭐가 유행하는지"를 감(gut feeling)으로만 판단. 체계적 트렌드 분석 도구가 없음. 경쟁력 있는 메뉴 개편 시기를 놓침
원가 변동 인지 지연 식자재 원가가 매출의 28~35%를 차지하지만, 유통사의 가격 인상을 수개월간 인지하지 못함. 마진 잠식, 연간 수천 달러 손실
감에 의존하는 메뉴 개편 어떤 메뉴를 추가/삭제할지 데이터 없이 직감으로 결정. 저마진 메뉴 유지, 고마진 기회 상실
경쟁사 모니터링 부재 경쟁 식당의 메뉴와 가격을 수작업으로 확인하거나, 아예 하지 않음. 가격 경쟁력 저하, 시장 포지셔닝 오류
기존 도구의 한계 Restaurant365, MarketMan 등은 $300+/월이며 올인원 솔루션이라 복잡하고, 소규모 식당에는 과도함. 도입 장벽이 높아 대부분 미사용

핵심 가치 제안: MenuPulse는 기존 올인원 솔루션의 절반 가격($149/월)으로, 식당 오너가 실제로 가장 필요로 하는 세 가지 -- 트렌드, 원가, 경쟁사 -- 에 집중한다. 복잡한 재고 관리나 POS 연동 없이, 인사이트 전달에만 특화된 경량 도구이다.

3. 기능 명세 (MVP)

MVP 범위는 8-10주 내 개발 완료를 목표로 하며, 아래 5개 핵심 기능으로 구성된다.

3.1 Trending Recipes & Menu Ideas

데이터 수집

  • 소셜 미디어 트렌드 집계: TikTok 음식 트렌드, Instagram #food 해시태그, Google Trends 데이터를 통합 수집
  • 수집 주기: 일간 배치 (실시간 아님)

트렌드 분석 및 리포트

  • 주간 "지금 뜨는 메뉴 아이디어" 리포트 생성 (카테고리별: 앙트레, 사이드, 디저트, 음료)
  • 트렌드 점수 산출: 검색량 + 소셜 언급 수 + 7일/30일 성장률의 가중 합산
  • 각 트렌드 항목에 간단한 레시피 개요 + 예상 원가 + 마진 추정치 포함

개인화 추천

  • 사용자의 업종(cuisine_type)과 가격대(price_range) 기반으로, 내 메뉴에 추가할 만한 아이템 추천
  • 시즌별 트렌드 캘린더: 발렌타인데이, 추수감사절, 할로윈 등 이벤트 메뉴 아이디어를 사전에 제공

3.2 Food Cost Tracker

인보이스 처리

  • 유통사 인보이스 업로드 지원: CSV, PDF 형식
  • AI 기반 자동 파싱 (OpenAI API): 품목명, 수량, 단가, 합계 추출
  • 품목명 정규화 (normalized_name): 서로 다른 유통사의 동일 품목 매칭

가격 추적 및 알림

  • 품목별 가격 히스토리 그래프 (시계열 차트)
  • 가격 변동 알림: 특정 품목이 사용자 설정 임계치(X%) 이상 상승 시 이메일/SMS 발송
  • 월별 원가 리포트: 카테고리별(육류, 해산물, 채소, 유제품 등) 집계

절감 제안

  • 대체 식자재 추천: "치킨 thigh가 15% 상승 -- 비슷한 원가의 대안: pork shoulder"
  • 시즌별 가격 예측: "매년 12월 소고기 가격 평균 12% 상승" 패턴 제공

3.3 Competitor Menu Monitor

  • 경쟁 식당 URL 등록 (사용자당 최대 10개)
  • 메뉴 변경 자동 감지: 새 메뉴 추가, 가격 변경, 메뉴 삭제 시 알림 발송
  • 가격 비교 대시보드: 내 메뉴 vs 경쟁사 동일/유사 메뉴 항목의 가격 병렬 비교
  • 지역 평균 가격 벤치마크: 동일 ZIP 코드 내 유사 업종의 평균 가격 참고치
  • 웹 스크래핑 기반 (Puppeteer/Playwright), 주 1-2회 크롤링

3.4 Cost Saving Recommendations

메뉴별 원가 분석

  • 현재 등록된 메뉴 아이템의 품목별 원가 분해 표시
  • 메뉴 아이템별 마진 순위: 가장 수익성 높은 메뉴 vs 손해 보는 메뉴 정렬

원가 절감 제안

  • "이 메뉴의 원가를 15% 줄이는 방법" 구체적 제안:
    • 대체 식자재 (더 저렴하면서 품질 유사한 재료)
    • 포션 최적화 (업계 표준 대비 과다 포션 감지)
    • 계절 식재료 활용 (현재 시즌에 저렴한 대안)
    • 벤더 변경 제안 (동일 품목의 타 유통사 가격 비교)

"죽은 메뉴" 감지

  • 마진이 낮고 주문 빈도도 낮은 아이템을 자동 식별
  • 메뉴에서 제거하거나 리뉴얼할 것을 권고

3.5 Dashboard

  • 이번 주 트렌드 요약: 상위 5개 트렌드 키워드와 점수
  • 원가 변동 요약: 가격이 오른 품목, 내린 품목 리스트
  • 경쟁사 변경 사항: 최근 감지된 메뉴/가격 변경
  • 내 메뉴 마진 현황: 전체 평균 마진, 최고/최저 마진 아이템
  • 액션 아이템 체크리스트: "치킨 가격 확인", "새 디저트 검토" 등 즉시 실행 가능한 할 일

4. 기술 스택

영역 기술 비고
프론트엔드 Next.js 14 (App Router) Tailwind CSS. SSR + 클라이언트 컴포넌트 혼합 구성.
백엔드 Supabase PostgreSQL + Auth + Storage + Edge Functions. 별도 서버 불필요.
데이터 파이프라인 Google Trends API, Puppeteer/Playwright, PDF 파싱 라이브러리 Google Trends API로 트렌드 데이터 수집. Puppeteer/Playwright로 경쟁사 메뉴 및 소셜 트렌드 스크래핑. PDF 파싱으로 인보이스 처리.
AI OpenAI API 인보이스 파싱 및 레시피 제안에 사용. 배치 처리 (주간/일간). 예상 비용: 고객당 월 $5~10.
알림 Resend (이메일), Twilio (SMS) 가격 변동, 경쟁사 변경, 주간 트렌드 리포트 발송.
배포 Vercel + Supabase Vercel로 프론트엔드 + Edge Functions 배포. Supabase 클라우드로 DB + Storage.

6. 화면 설계

각 화면의 레이아웃과 핵심 컴포넌트를 기술한다. 상세 와이어프레임은 디자인 단계에서 별도 제작한다.

6.1 Dashboard (메인 화면)

상단
이번 주 핵심 인사이트 카드 3개 (트렌드 1위, 최대 가격 변동 품목, 경쟁사 변경 알림)
좌측 영역
트렌드 피드 -- 스크롤 가능한 카드 리스트. 키워드, 점수, 간략 설명.
우측 영역
원가 변동 요약 (가격 상승/하락 품목) + 미확인 알림 배지 카운트.
하단
액션 아이템 체크리스트. 사용자가 완료 처리할 수 있는 할 일 목록.

6.2 Trends

상단 필터
카테고리 필터 탭: 전체 / 앙트레 / 사이드 / 디저트 / 음료
메인 영역
트렌드 카드 그리드. 각 카드에 키워드, 트렌드 점수 미니 차트, 예상 마진 표시.
상세 뷰
카드 클릭 시 슬라이드 패널 또는 모달: 레시피 개요, 예상 원가 분해 (재료별), 시즌 적합성 태그.

6.3 Food Cost Tracker

상단
인보이스 업로드 영역 (드래그 앤 드롭 + 파일 선택). 파싱 상태 표시.
중앙
품목별 가격 시계열 그래프. 품목 검색 및 필터. 기간 선택 (1개월/3개월/6개월/1년).
우측 사이드바
가격 변동 알림 설정 (품목별 임계치 % 입력).
하단
월별 카테고리별 원가 파이차트. 전월 대비 변동률.

6.4 Competitor Monitor

좌측
등록된 경쟁사 목록. 각 항목에 식당명, 마지막 업데이트 시각, 상태 뱃지.
중앙
변경 사항 피드: 시간순 정렬. 새 메뉴 추가(녹색), 가격 변경(황색), 메뉴 삭제(적색) 구분.
하단
가격 비교 테이블: 내 메뉴 아이템과 경쟁사 동일/유사 메뉴의 가격을 나란히 표시.

6.5 My Menu Analysis

메인 테이블
메뉴 아이템 목록: 이름, 판매 가격, 식자재 원가, 마진%, 주문 빈도. 정렬 가능.
시각화
마진 순위 가로 막대 차트. 상위 5개(녹색), 하위 5개(적색) 강조.
추천 패널

  • 캐싱: 동일 트렌드 키워드에 대한 레시피 제안은 7일간 캐싱. 인보이스 파싱 결과는 영구 저장.

10. 리스크 및 대응

1. 데이터 소싱의 기술적 난이도

트렌드 데이터를 소셜 미디어에서 안정적으로 수집하는 것은 API 제한, 사이트 구조 변경 등으로 쉽지 않다.

대응: 초기에는 수동 큐레이션 + Google Trends API 조합으로 시작한다. 고객 수 증가에 따라 점진적으로 자동화 범위를 넓힌다. TikTok/Instagram은 공식 API가 아닌 트렌드 집계 서드파티 서비스 활용을 검토한다.

2. 인보이스 파싱 정확도

유통사마다 인보이스 형식이 다르며, PDF 레이아웃이 비정형이라 파싱 오류가 발생할 수 있다.

대응: 주요 유통사(Sysco, US Foods, Performance Food Group) 템플릿을 우선 지원한다. 미지원 형식은 CSV 업로드로 폴백한다. 파싱 결과를 사용자가 확인/수정할 수 있는 UI를 제공한다.

3. 경쟁사 메뉴 스크래핑 불안정

경쟁 식당 웹사이트의 구조 변경, 봇 차단 등으로 스크래핑이 실패할 수 있다.

대응: 수동 입력 폴백을 항상 제공한다. 주요 레스토랑 플랫폼(Toast, Square, Wix Restaurants)의 메뉴 페이지 구조에 맞춘 전용 파서를 개발한다. 스크래핑 실패 시 사용자에게 알림 후 수동 업데이트 유도.

4. 식당 오너의 낮은 IT 리터러시

타겟 사용자의 상당수가 복잡한 소프트웨어에 익숙하지 않다.

대응: 극도로 간단한 UI를 지향한다. 핵심 인사이트는 앱 접속 없이도 이메일/SMS 알림으로 전달한다. 온보딩 플로우를 5단계 이내로 설계하고, 첫 사용에서 가치를 즉시 보여준다 (예: 무료 트렌드 리포트 즉시 제공).

11. MVP 타임라인 (8-10주)

주차 작업 범위 상세 내용
Week 1-2 기반 구축 Supabase 프로젝트 셋업. DB 스키마 생성 및 마이그레이션. Supabase Auth 연동. Next.js 프로젝트 초기화 + Tailwind 설정. 기본 CRUD API (메뉴 관리).
Week 3-4 인보이스 + 원가 추적 인보이스 업로드 UI (드래그 앤 드롭). PDF/CSV 파싱 파이프라인 (OpenAI API 연동). 파싱 결과 확인/수정 UI. 가격 히스토리 저장 및 시계열 차트.
Week 5-6 트렌드 엔진 Google Trends API 연동. 트렌드 데이터 수집 배치 잡 (Supabase Edge Function + cron). 트렌드 점수 산출 로직. 트렌드 대시보드 UI. 레시피 제안 생성 (OpenAI API 배치).
Week 7 경쟁사 모니터링 경쟁사 URL 등록 UI. Puppeteer 기반 메뉴 스크래핑 파이프라인. 변경 감지 로직 (diff). 알림 생성.
Week 8 원가 절감 + 마진 분석 메뉴 아이템별 원가 분해 표시. 마진 순위 차트. 원가 절감 추천 로직 (규칙 기반 + AI 보완). "죽은 메뉴" 감지 알고리즘.
Week 9 대시보드 + 알림 + 설정 메인 대시보드 조합. Resend 이메일 알림 연동. Twilio SMS 알림 연동. 설정 페이지 (프로필, 유통사, 경쟁사, 알림).
Week 10 마무리 통합 테스트 및 버그 픽스. 랜딩 페이지 제작. 온보딩 플로우 구현. 배포 및 모니터링 설정.
